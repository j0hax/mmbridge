# AGENTS.md

## Overview

Go daemon bridging a Minecraft Java server (log tail + RCON/FIFO) with a Matrix
room via the Application Service API. Single binary in `cmd/mmbridge`; all other
code lives under `internal/`.

## Commands

- Build: `go build ./cmd/mmbridge/`
- Verify: `go vet ./... && gofmt -l .` (gofmt output must be empty) then `go test ./...` (there are currently no test files)
- Run: `./mmbridge -config config.yaml -log-level debug`
- Generate Matrix appservice registration: `./mmbridge -config config.yaml -generate-reg > registration.yaml`
- Nix: `nix build` or `nix develop`. `flake.nix` pins `vendorHash`; update it whenever `go.mod`/`go.sum` change or Nix reports a hash mismatch.

The `-config` flag defaults to `config.yaml`. Start from `config.example.yaml`.
`config.yaml` is not covered by `.gitignore`; do not commit real tokens.

## Architecture

- `internal/bridge/bridge.go` is the coordinator: tails the Minecraft log into
  Matrix and forwards Matrix messages to Minecraft via `tellraw`.
- Transport choice: if `minecraft.rcon_address` is set, RCON is used and
  `minecraft.fifo` is ignored. Otherwise commands are written to the FIFO.
  Config validation requires at least one of them.
- `internal/logtail` seeks to end-of-file on startup, so only new log lines are
  bridged. It only recognizes lines shaped like
  `[HH:MM:SS] [Server thread/INFO]: ...`; chat/join/leave/death/advancement/
  server-message detection lives there.
- `internal/matrix` wraps mautrix appservice. Ghost users are
  `@<user_prefix><lowercased player>:<domain>`, created lazily on first message.
  Only text messages in `matrix.room_id` from users that are neither the bot nor
  a ghost are forwarded. Avatar fetches hit Mojang/session APIs in a background
  goroutine and failures are logged, not fatal.
- `internal/config` maps YAML to Go fields. Note the mismatch:
  `relay_server_messages` -> Go field `RelayServer`.
- Secret precedence: inline values win; `*_file` variants are read only when the
  corresponding inline value is empty.
- `internal/formatting` intentionally supports only a small Markdown <-> legacy
  `§` subset (`**bold**`, `*italic*`, `~~strike~~`, `<u>`, `</u>`), not full
  Markdown or arbitrary Minecraft formatting.
- `internal/mojang` fetches skins/faces for ghost avatars and requires outbound
  internet access.

## Gotchas

- Registration generation hardcodes the appservice URL as
  `http://localhost<listen_address>` in `cmd/mmbridge/main.go`. Adjust that if
  the homeserver cannot reach the bridge via localhost.
- `tellraw` JSON is assembled manually in `bridge.go`; preserve string escaping
  when changing message text.
- Config changes usually need to be mirrored in three places:
  `internal/config/config.go`, `config.example.yaml`, and the YAML generated by
  `module.nix`. Keep `_file` credential paths in sync with systemd
  `LoadCredential` names.
- `mmbridge` and `result` in the repo root are build artifacts (ignored); do not
  edit or commit them.

## Conventions

- Go module import path is `github.com/johannes/mmbridge` even though the Git
  remote is `j0hax/mmbridge`; use the module path for imports.
- No CI or lint configuration exists. `gofmt` and `go vet` are the available
  automated checks.
